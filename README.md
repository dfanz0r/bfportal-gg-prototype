# bfportal.gg prototype

A TypeScript rewrite of [bfportal.gg](https://bfportal.gg), built with TanStack Start,
SolidJS and Postgres. The approach, data model and open decisions are in
[PLAN.md](PLAN.md).

## Requirements

- Node 22.12 or newer
- pnpm 11
- Docker or Podman with a compose plugin, for the local Postgres

## Getting started

```bash
pnpm install
cp .env.example .env.local   # then fill in BETTER_AUTH_SECRET
pnpm db:up                   # Postgres 18 on localhost:5433
pnpm db:migrate
pnpm dev
```

The dev server runs on http://localhost:3000, and http://localhost:3000/api/health
reports whether it can reach the database.

Signing in needs a Discord OAuth application. Put its client id and secret in
`.env.local` and add `http://localhost:3000/api/auth/callback/discord` as a redirect
URI.

## Scripts

| Script | Purpose |
|---|---|
| `pnpm dev` | Dev server with hot reload |
| `pnpm build` | Production build into `.output/` |
| `pnpm start` | Run the production build |
| `pnpm typecheck` | Type-check without emitting |
| `pnpm db:up` | Start the local Postgres container |
| `pnpm db:generate` | Write a migration from changes to `src/server/db/schema.ts` |
| `pnpm db:migrate` | Apply pending migrations |

`src/routeTree.gen.ts` is generated by the Vite plugin during `pnpm dev` and
`pnpm build`. Do not edit it by hand, and run one of the two after adding a route
before type-checking.

`pnpm start` does not read `.env.local`; the production server takes its
configuration from the environment.

## Database

- The schema is `src/server/db/schema.ts`; migrations are in
  `src/server/db/migrations`.
- `src/server/db/auth-schema.ts` holds Better Auth's tables. Regenerate it with
  `pnpm dlx auth generate --config src/server/auth/index.ts --output src/server/db/auth-schema.ts`
  after changing the auth configuration.
- The local Postgres is published on port 5433 so the old site's dev database can
  keep 5432. The one-off import reads the old one through `LEGACY_DATABASE_URL`.
